# What `tools/list` returns from the grafana-mcp this stack runs: one tool name per line.
#
#   chart:    grafana-community/grafana-mcp 0.27.1
#   server:   mcp-grafana 2.0.1
#   values:   infra/observability/grafana-mcp.values.yaml
#   recorded: 2026-10-08, studio-rancher-desktop
#
# This file is why a name on the agent's allowlist (GrafanaOptions.AllowedTools) cannot be a
# guess: GrafanaMcpAllowlistTests fails when the allowlist names a tool that is not here, and
# when the chart version above is not the one the Tiltfile and scripts/e2e/lib/deps.sh pin.
# So moving the pin means recording this again, and a renamed tool is a red build instead of
# a Degraded row somebody notices a week later.
#
# Record it from the agent's pod, which already holds the caller token (it is never printed):
#
#   kubectl -n hephaisto exec deploy/hephaisto -c hephaisto -- sh -c 'curl -s -X POST \
#     "$Grafana__McpUrl" -H "Authorization: Bearer $Grafana__ServiceAccountToken" \
#     -H "content-type: application/json" -H "accept: application/json, text/event-stream" \
#     -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/list\"}"' \
#     | sed 's/^data: //' | jq -r '.result.tools[].name' | sort
#
# The list depends on the server's flags as much as on its version: `api` (grafana_api_request)
# and `snapshot` are disabled in the values file, as in production, and are absent below.
